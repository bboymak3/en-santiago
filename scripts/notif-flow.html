Sistema de Notificaciones - HolaX
Flujo completo: Eventos, API, Base de Datos y UI
1. Eventos Disparadores (Triggers Automáticos)
🏪 Nuevo Negocio
POST /api/businesses
Notifica: Admin (siempre)
+ Todos (si toggle ON)
💼 Nuevo Empleo
POST /api/jobs
Notifica: Admin (siempre)
Link: /admin.html#jobs
⭐ Nueva Reseña
POST /api/reviews
Notifica: Dueño del negocio
Link: /negocio/{id}
💎 Solicitud Premium
POST /api/plans/request-upgrade
Notifica: Admin (siempre)
Link: /admin.html#premium
↓
2. Verificación de Configuración
1Consultar admin_settings.notifications_enabled = '1' ?
2Si es '0' → NO se envía notificación (fin del flujo)
3Si es '1' → Buscar admins activos: SELECT id FROM users WHERE role='admin' AND is_active=1
4Si notify_all_users = '1' → También buscar usuarios no-admin activos
↓
3. Insertar en Base de Datos (D1)
1INSERT INTO notifications (user_id, type, title, message, link)
2Se usa env.DB.batch() para insertar múltiples filas (1 por destinatario)
3Cada notificación queda con is_read = 0 y created_at = datetime('now')
4Error en notificación → no falla la operación principal (try/catch silencioso)
↓
4. API /api/notifications (Endpoints)
GGET /notifications → Lista propia con paginación (?all=1 admin ve todas)
GGET /notifications?action=unread_count → Solo count (polling cada 30s)
GGET /notifications?action=settings → Config (solo admin)
PPOST /notifications → Crear manual (admin: broadcast/array)
APATCH /notifications → mark_read / mark_all_read / update_settings
DDELETE /notifications → Eliminar (admin: cualquier, user: propias)
↓
5. Interfaz de Usuario
1Dashboard: Campanita 🔔 con badge rojo (count no leídas) → Polling 30s
2Dropdown: Lista con iconos por tipo + "Marcar todas" + click → marca como leída + navega al link
3Admin Panel: Tab "Notificaciones" con historial global (todas las notifs del sistema)
4Compositor: Enviar a todos / solo admins / usuario específico (con búsqueda)
5Admin Settings: Toggle "Notificar al registrar negocio" + "Notificar a todos los usuarios"
